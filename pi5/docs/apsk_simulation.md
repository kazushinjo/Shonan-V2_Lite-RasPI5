# 16APSK/32APSK受信のシミュレーション結果(2026-10-28)

`pi5/scripts/dvbs2_loopback_sim.py` で、gr-dtv(GNU Radio標準)のDVB-S2送信信号に
振幅変化(0.3倍)・周波数ずれ(2e-4 cycle/sample)・位相・白色雑音を加え、`pi5/rx/shonan_rx.py` と同じ
受信系(gr-dvbs2rx + `gr-dvbs2rx_pi5_bringup.patch` + `gr-dvbs2rx_apsk.patch`)で復調した。
ロングフレーム、パイロットあり、ロールオフ0.35、2サンプル/シンボル、100フレーム。
環境: Mac(Apple Silicon)、GNU Radio 3.10.12、gr-dvbs2rx 130c315。

PASS = ロック後に受信したTSパケットに誤り・抜け・順序違いが無い。

## 不合格3件の原因(周波数同期の立ち上がり)

送信した点の列とPL同期(plsync_cc)の出力をフレームごとに突き合わせて調べた
(QPSK 9/10、10.4 dB、周波数ずれ2e-4 cycle/sample)。

| ロック後のフレーム | 周波数補正 | 実効SNR |
|---|---|---|
| 0〜29 | なし(粗い周波数推定が`freq_est_period`=30フレーム分そろうまで、補正もパイロットによる位相補正もせずに出力する) | 復号不能 |
| 30〜58 | 粗い補正のみ | 5.0 dB |
| 59以降 | 完了 | 10.3 dB(設定どおり) |

- 復号だけを試すと(同期を通さず変調器の出力に雑音を加える)、QPSK 8/9・9/10・32APSK 9/10とも誤りなし。
  周波数ずれ0でも最初から誤りなし。
- 実効SNR 5 dBの期間は、必要C/Nの低いMOD-COD(QPSK 3/5など)なら復号できるが、高い符号化率はできない。
  そのため高い符号化率ほど、映像が出るまでに長くかかる(ロック後およそ60フレーム。QPSKのフレームは
  約33,000シンボルなので、1 Msps で約2秒、333 kS/s で約6秒。32APSKはフレームが短いので早い)。
- 250フレーム流して最初の70フレームを除くと、QPSK 8/9・9/10(10.4 dB)、32APSK 9/10(20.1 dB)とも
  PASS(誤り・抜けなし)。
- 本家gr-dvbs2rxの動作で、APSKパッチの有無に関係しない(パッチ無し版でも結果が完全に同じ)。
- `freq_est_period`を10・5に下げると立ち上がりは早くなるが、5ではQPSK 1/4(3 dB)が不合格になった。
  はっきり良くなる値は無いため、実機で実績のある既定値30のままとする。
- rotator_ccの出力バッファ上限、LDPCの反復回数(25→100)は結果に影響しなかった。
